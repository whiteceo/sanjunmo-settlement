## 7. 미수행 — 12절 인수인계 메모로 이관

작업 1(본인 PASS 전체 사이클)은 **가상계좌 결제(P21)를 제외하고 완결**했다 — 가입 · 쿠폰 · 포인트 · 결제 · 수강 · 1:1 문의 · 환불 신청 · 관리자 환불 처리 · 탈퇴 화면 진입 · DI 중복 체크.

남은 항목과 재개 방법은 **`12. 인수인계 메모`** 에 우선순위로 정리했다.

### 수행하지 않은 것 (의도)

- **[정산 마감]** — 지시서대로 누르지 않았다(해제 불가)
- **관리자 5회 오입력 강제 잠금** — 공용 관리자 계정이 잠기면 사람이 다시 못 들어온다
- **엑셀 실제 다운로드** — 개인정보 파일이라 버튼 존재·사유 모달까지만 확인
- **외부 발송 유발 버튼** — 인증번호 발송 등은 한도를 소모하고 실제로 나가므로 누르지 않았다
- **다른 테스터 데이터** — `test1~3` · `qa-lem` · `qa-psj` · `qa-nsw` 회원과 주문은 열람도 하지 않았다. 주문 목록에 보인 `박*정` 11.05 건은 건드리지 않았다

### 금지사항 준수

`.env` 미열람 · DB 미접속 · 코드 미수정 · 커밋 없음. 개인정보가 보이는 캡처를 만들지 않았고, 본 문서에 실명·연락처·이메일 원문을 적지 않았다.

## 34. A17 종결 — 결함 아님 (설계된 동작)

**A17(PG 대사 0건을 Gate 1 이 "검증 통과"로 판정 — fail-open 우려)은 결함이 아니다. 폐기한다.**

`[정산 마감]` 을 누를 필요 없이 코드 한 곳으로 종결된다 — `app/Services/Settlement/SettlementCloseGateService.php::pgBlocks()`:

```php
$recon = $this->gateRepository->pgReconciliation($targetMonth);

// 대사 기록이 없는 달은 막지 않는다 — 199 ⑤ 가 차단으로 지정한 것은
// UNKNOWN_MISMATCH(Gate 1)와 허용 오차 초과(Gate 2) 둘뿐이다. 기록 없음은 경고다
if ($recon === null) {
    return [];
}
```

**DECISIONS 199 ⑤ 가 마감 차단 사유를 두 가지로만 한정했고, "기록 없음"은 차단이 아니라 경고로 두는 것이 결정사항이다.** 월간 정산 화면의 `▲ PG 정산 원장 대사 기록이 없습니다(ADMN-SETT-004). 마감 전에 대사를 실행하세요.` 가 바로 그 설계된 경고다(S6).

따라서 두 화면의 판정이 엇갈린 것이 아니라, **"차단"과 "경고"를 의도적으로 분리한 것**이다. fail-open 이 아니라 fail-warn 이다.

- **0절의 A17 을 결함 목록에서 제외한다.**
- **30절 오픈 전 필수 10건에서 A17(10번)을 뺀다 → 9건.**
- **33절 다음 회차 1순위에서 A17(3번)을 뺀다 → 2건.**

> 이로써 이 회차에서 통제 재현 · 설정값 확인 · 코드 확인으로 폐기한 자체 오판이 **8건**이 됐다(강좌 목록 헤더 · 권리자 매핑 스코어카드 · `/sj-admin/limits` 404 · A7 감사 로그 · X1 · X2 · V4 배속 · A17). 전부 "상관관계 또는 화면 표면만 보고 결함으로 올린 것"이 원인이다.
