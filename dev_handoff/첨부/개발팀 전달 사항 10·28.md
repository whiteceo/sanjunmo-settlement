## 4. 운영 관제 준비(오픈 전) 지금은 기록은 잘 남지만 경보를 보내는 장치가 거의 없다

- **먼저 할 것**: 10분 · 1분마다 도는 배치(`payments:expire-virtual-accounts` · `notifications:send-campaigns` · `coupons:issue-scheduled`)와 토스 결제 웹훅의 실패 · 미실행 경보. 지금 스케줄 18개에 실패 훅(`onFailure` 등)이 0건이다.
- **확정(white 10-27)**: 감시는 **AWS CloudWatch**(서버 지표 · 로그 · 경보), 경보 받는 곳은 **담당자 이메일 · 휴대폰 문자**, 발송은 이미 연동된 **네이버 클라우드 SENS**. 유료 도구(Sentry 등)는 쓰지 않음.
- **이 기준으로 할 일**: ① 앱 로그를 CloudWatch Logs로 보내고 ERROR 건수 · 500 응답 지표에 경보(Metric Filter + Alarm) ② `/up` 을 CloudWatch Synthetics 또는 Route 53 헬스 체크로 주기 확인 ③ 배치마다 `onFailure` 에서 SENS 문자 · 이메일 발송, 1분 · 10분 배치는 마지막 실행 시각을 지표로 남겨 "미실행" 경보 ④ 결제 웹훅 실패 · 환불 PG 취소 실패는 앱에서 바로 SENS 발송. 경보 문구 · 수신자 목록은 설정값으로 둠.
- **그다음**: 결제 승인 실패율 · 환불 법정 기한 D-1, 관리자 로그인 실패 급증 · 대량 개인정보 다운로드, 정산 마감 차단 게이트 · 감사 해시 체인 불일치, 외부 연동(SENS 자체 · 이니시스 · 국세청 · OVP) 실패율. SENS 자체가 실패할 때를 대비해 CloudWatch 경보는 AWS SNS 이메일로도 한 갈래 받음.
