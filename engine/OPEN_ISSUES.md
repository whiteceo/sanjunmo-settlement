## 2. FAIL 판정

### OI-01 D-09 — 정본 모순: 5단계 '복원 후 한도'와 D-9 기대값

| 항목 | 내용 |
| :--- | :--- |
| 정본 A | V2 §8.3 5단계 2) L208 `복원 후 사용가능 한도 = total_cap_amount − cap_consumed_amount + 승인된 한도 복원액`, 3) L209 `신규 확정액 = min(신규 발생액, 복원 후 사용가능 한도)`, 5) L211 `cap_consumed = 기존 + 신규 확정액 − 복원액` |
| 정본 B | V4 부록 D D-9 L291: 신규 40만 > 잔여 한도 15만, 옵션 B 10만 → 소멸 25만 · 신규 확정 15만 · 지급 대상 5만 · **복원 반영 후 잔여 한도 10만** |
| 모순 | A로 계산하면 잔여 한도 R₀ · 복원 10만에서 `신규 확정 = min(40만, R₀ + 10만)`, `복원 후 잔여 = R₀ − 신규 확정 + 10만`. 신규 확정 15만(< 40만)이면 R₀ + 10만 = 15만 → R₀ = 5만 → 잔여 0. 잔여 10만이 되려면 R₀ = 15만인데 그러면 신규 확정 = 25만. **'15만 확정'과 '잔여 10만'이 A의 식으로 동시에 나올 수 없다.** D-9는 복원을 당월 신규 한도 적용 뒤에 반영하는 순서로 계산한 값이다. |
| 엔진 | A(V2 SSOT)를 따른다: 소멸 15만 · 신규 확정 25만 · 지급 대상 15만 · 잔여 0 |
| 확인 요청 | 복원액을 같은 달 신규 발생액의 한도에 쓸 수 있는가(A) / 다음 달부터 쓰는가(D-9). A가 맞으면 D-9 기대값 수정, D-9가 맞으면 V2 2) · 3)의 '복원 후 한도'를 '복원 전 한도'로 수정 |

### OI-02 D-14 — 입력 부족: 기타소득 SKU 2건

- VAT 부분(총액 1,100,000 → 공급가액 1,000,000 · 부가세 100,000)은 일치.
- 기타소득 4건(`min_tax_exempt_each` · `per_sku_other_income_amount` 등)은 계산 입력이 없다. D-14는 '각 기타소득금액 4만 원'만 주고, 과세표준(수입금액) · 소득 조항(C15 의제 60% / C17 의제 없음) · 지급 라인 성격이 없다. 정본이 TX-06 · TX-07 과세사업자의 기타소득을 무엇으로 판정하는지도 없다(Case 3 · 8은 TX-07 원천징수 비대상 전제, TAX.md 확인 필요 2 · 3). 지어내지 않고 입력하지 않았다.
- 엔진은 판정 단위(`tax_threshold_unit_key`)별 과세최저한을 구현했다(샘플 `H-LEE` C15 인세 15,000 → 기타소득금액 6,000 ≤ 50,000 → 0원, Case 2-B 80,000 → 과세 통과).
- 확인 요청: D-14 수치 회귀용 입력(SKU별 지급액 · 소득 조항 · 수취인 세무 케이스).

### OI-03 D-08 — 입력 부족: 위탁 음수 잔액 '전액 상쇄'

- 정본 V4 L290: 위탁 음수 잔액 −100원 전액 상쇄 → 기말 0원, 변동은 원잔액 부호(−100).
- fixture 입력은 잔액 −100뿐이고 상쇄할 당월 위탁 순액(양수)이 없다. 엔진은 4단계에서 잔액을 넣고(`net_2_2 = 0 − 0 + (−100)`) 10단계에서 음수 −100을 위탁 전용 잔액으로 다시 적재해 기말 −100이 된다. 변동 부호(−100)는 일치.
- 당월 위탁 순액 ≥ 100을 넣으면 기말 0 · 변동 −100(엔진 등식 검증 통과). 확인 요청: D-8의 당월 위탁 정산 입력값.

## 7. 구현 한계(엔진 오류는 아니나 알려 둠)

- P2.1 반품(`refund_lines` pipeline 2.1)은 계약의 첫 BUSINESS 인세 라인에서 차감한다. 기타소득(OTHER) SKU별 라인으로 나뉜 인세의 반품을 SKU 라인으로 보내는 처리는 아직 없다(fixture 없음).
- 마감 후 조정 라인(`adjustments`)은 SPEC 기본값 `hold` — 계산에 넣지 않고 `pending_adjustments`로만 출력한다(`provisional` 모드는 Q-23 확정 후 구현).
- 9단계 6단계 재검증(현금 가용액 < 상계액)은 1회만 재계산한다.
