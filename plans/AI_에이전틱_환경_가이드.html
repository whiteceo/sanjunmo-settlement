AI AGENT VS AGENTIC SYSTEM

“우리는 AI를 ‘도구’로 쓰고 있나요, ‘시스템’으로 사용하고 있나요?”

파편화된 개인별 챗봇 활용(AI Agent)을 넘어, 기획·디자인·개발이 하나의 정본으로 맞물리는 AI 에이전틱 시스템(Agentic System)

SECTION 01 · CONCEPTUAL ARCHITECTURE

전체 시스템 조감도 — 안건 발화부터 자동 검수까지

외부 툴 없이도 Git 내 LATEST_TASK.md와 QUESTIONS.md만으로 전 직군의 AI가 하나로 움직입니다.

PO / PM 그룹 안건 발화 & 역질문 결정

화면코드를 외울 필요 없이 비즈니스 안건만 말하면 AI가 연관 문서를 고치고 LATEST_TASK.md를 발행합니다.

UIX 디자이너 디자인 토큰 & 핵심 UX 집중

Figma Auto Layout·변수만 유지하면 AI가 MCP로 시안 수치를 직접 읽어 화면 골격으로 변환합니다.

FE / BE 개발자 아키텍처 & 엣지케이스 승인

기획서를 뒤지는 대신 로컬 AI가 브리핑하는 LATEST_TASK.md 요약을 보고 구현을 지휘합니다.

SECTION 02 · 4-STAGE WORKFLOW

4단계 에이전틱 파이프라인

각 단계의 산출물이 다음 단계 AI의 입력으로 직결되어 재작업과 오해를 원천 차단합니다.

01 정본화 구두 합의 제로

정본에 적히지 않은 요구사항은 존재하지 않는 것으로 간주하여 기준을 단일화합니다.

02 시각화 코드 작성 전 검증

프로토타입 또는 Figma 시안에서 화면 흐름을 먼저 확정한 뒤 본 개발에 진입합니다.

03 구현 할루시네이션 차단

작업 화면에 해당하는 1장 요약본(Digest)만 주입해 AI가 다른 화면 규칙과 혼동하지 않습니다.

04 검수 기계적 대조 자동화

수수료율·기한·상태코드 등 정본 수치와 실제 코드의 일치 여부를 스크립트가 1초 만에 검사합니다.

SECTION 03 · 2-REPO ARCHITECTURE

저장소 물리적 분리 — 기획 정본 Repo vs 서비스 코드 Repo

기획·디자인 자산과 실제 구동 코드를 분리해 권한 충돌과 AI 컨텍스트 오염을 막습니다.

이유 1 AI 컨텍스트 오염 원천 방지

프로토타입 HTML과 실제 React/Spring 코드가 한 폴더에 섞여 AI가 레거시 시안을 복사하는 사고를 차단합니다.

이유 2 직군별 승인 권한 명확화

spec-repo의 최종 머지 권한은 PO/PM에게, service-repo는 개발팀에 두어 기준 문서를 보호합니다.

이유 3 단방향 캐시 동기화

개발 환경에서는 sync-spec.sh 명령 한 줄로 최신 정본과 LATEST_TASK.md를 즉시 가져옵니다.

SECTION 04 · TOKEN & CONTEXT EFFICIENCY

토큰 94% 절감 — 화면별 핀셋 요약본(Digest) 주입

수천 줄짜리 전체 기획서를 매번 읽히는 대신, 작업할 화면 1개에 필요한 1장 요약본만 AI에 주입합니다.

digests/{화면코드}.md + CORE_RULES.md 딱 2개만 로드 • 단순 텍스트·수식 검사는 LLM 대신 로컬 파이썬 스크립트가 0토큰 처리

원칙 1 화면별 1장 요약본 (Digest)

PO가 정본을 수정할 때 각 화면 코드에 필요한 필드·수식·모달만 뽑은 1장짜리 요약 카드가 자동 갱신됩니다.

원칙 2 스크립트 우선 (0 토큰 검수)

금지어 스캔·정규식 대조 등 단순 반복 검수는 AI 토큰을 쓰지 않고 로컬 스크립트가 즉시 처리합니다.

원칙 3 1화면 완료 시 세션 리셋

대화 기록이 길어질수록 토큰이 기하급수적으로 늘어나므로, 화면 1개 완료마다 /clear로 초기화합니다.

SECTION 05 · 2-TRACK UI STRATEGY

화면 성격에 따른 2-Track UI 전략

브랜드 경험이 중요한 고객 화면과, 빠른 CRUD 생산성이 중요한 어드민 화면의 제작 경로를 분리합니다.

Track A 핵심 시안 캡처 대신 Figma 노드 데이터 직결

이미지를 눈대중으로 베끼는 것이 아니라, Figma에 정의된 여백·컬러 변수·반응형 규칙을 코드로 그대로 가져옵니다.

Track B 핵심 어드민 화면 일관성 100% 유지

수십 개의 어드민 화면을 만들어도 4가지 표준 골격(Archetype) 안에서 생성되므로 UI가 흔들리지 않습니다.

SECTION 06 · FEEDBACK LOOP & FAST-TRACK

지시 전달 · 역질문 수렴 & 변경 패스트트랙

기본은 외부 툴 없이 Git 내 마크다운 파일 2개(LATEST_TASK.md · QUESTIONS.md)로 완결됩니다.

💡 사내 업무플랫폼(자체 구축 게시판)이나 외부 협업 툴과 연동하려면?

Git 기본 구조 위에 사내 업무플랫폼 경량 API 3종(다중 프로젝트·담당자 자동 매핑) 또는 Google Workspace를 얹는 확장 제안서입니다.

SECTION 07 · 5 CORE AI SKILLS

직군별 5대 AI 슬래시(/) 스킬 요약

각 직군은 복잡한 프롬프트 대신 표준화된 슬래시 명령어 5개로 시스템을 구동합니다.

PO / PM

/doc-update

자연어 안건을 받아 연관 화면코드를 자동 탐색하고 정본·Digest·LATEST_TASK.md를 동시 갱신합니다.

UIX 디자이너

/proto-gen

Figma MCP 디자인 시안 또는 4대 표준 어드민 골격을 기반으로 검증용 프로토타입을 생성합니다.

FE / BE 개발자

/code-gen

LATEST_TASK.md와 해당 화면 Digest 1장만 핀셋 로드하여 프로덕션 코드와 테스트를 작성합니다.

공통 · CI

/spec-check

정본 수식·필드·금지어와 실제 구현 코드를 대조하여 정합성 리포트를 출력하고 미비점을 잡아냅니다.

리뉴얼 · 레거시

/reverse-spec

문서가 없는 기존 레거시 소스코드를 역분석하여 화면 명세서 초안과 미정의 질문 목록을 추출합니다.

🚀 우리 프로젝트 유형에 맞는 도입 순서와 AI 주입용 실행 명세서(.md)

신규 구축 / 리뉴얼 / 운영 고도화별 도입 로드맵을 확인하거나, AI 에이전트에게 바로 읽힐 마크다운 정본을 다운로드하세요.

📥 AI용 MD 파일 다운로드
PROJECT ONBOARDING ROADMAP · 별도 페이지

프로젝트 유형별 AI 에이전틱 환경 도입 로드맵

STEP 1

저장소 · 스킬 세팅

AI에게 AI_에이전틱_환경_구축.md를 읽혀 폴더 구조와 5대 스킬을 자동 생성합니다.

STEP 2

화면코드 체계 부여

핵심 도메인별 화면 고유 코드와 CORE_RULES.md(절대 수식·용어)를 먼저 정의합니다.

STEP 3

Digest 자동화 가동

정본 수정 시 화면별 1장 요약본과 LATEST_TASK.md가 생성되는지 확인합니다.

STEP 4

시범 도메인 1개 운영

안건 1건을 골라 PO 발화 → UIX/개발 AI 반영 → /spec-check까지 1사이클을 돌립니다.

STEP 5

Pre-commit 게이트

검수 스크립트를 Git Hook 및 PR 체크에 연결하여 정합성 유지를 시스템으로 고정합니다.

📖 핵심 용어 사전 (Glossary)

용어 (약어) 한글 명칭 실무 역할 및 쉬운 풀이
SSOT
Single Source of Truth		 단일 정본 기획서·정책서가 여러 곳에 흩어지지 않고 오직 spec-repo/docs/의 문서만 절대 기준으로 삼는 원칙.
LATEST_TASK.md 최신 안건 작업 지시서 PO가 안건을 반영할 때 Git에 자동 생성되는 지시서. 개발자·UIX의 로컬 AI가 git pull 직후 스스로 읽고 이번 할 일을 파악함.
Digest
Screen Digest		 화면별 1장 요약본 전체 정본 중 특정 화면 1개 구현에 필요한 필드·상태·모달·수식만 1장으로 자동 추출한 AI 핀셋 주입용 카드.
MCP
Model Context Protocol		 외부 도구 직결 통로 AI가 로컬 파일뿐 아니라 Figma 디자인 시안, 사내 업무플랫폼 API 등 외부 데이터를 실시간으로 읽어오는 표준 규격.
Archetype 표준 화면 골격 (4종) 디자인 시안 없이도 백오피스 어드민의 통일성을 유지하는 4대 레이아웃 틀 (List-Modal, Detail-Form, Stats-Dashboard, Tabs-Complex).
Fast-Track (L1~L3) 변경 등급별 경량 경로 신규/대규모(L1) · 로직 변경(L2, UIX 생략) · 단순 문구/긴급 패치(L3, 선조치 후동기화)로 나누어 속도를 높이는 규칙.
Greenfield / Brownfield 신규 구축 / 레거시 운영 백지상태에서 새로 만드는 프로젝트(Greenfield)와 기존 레거시 코드 위에서 고도화하는 프로젝트(Brownfield).

🔌 자사 피드백 전달 방식 — Git 코어 & 사내 업무플랫폼 확장 연동 제안

Option A (권장 확장) 사내 업무플랫폼 경량 API

사내 플랫폼은 자체 구축 시스템이므로 AI로 경량 API 3종만 추가하면 됩니다. 다중 프로젝트 ID와 부서별 담당자 지정은 초기 1회 동기화한 project-meta.json을 통해 AI가 안건 도메인에 맞춰 자동 배정합니다.

Option B (대안 확장) Google Workspace 연동

사내 플랫폼 API 협의 전이라도 Google Docs/Sheets 플러그인이 기본 내장되어 있어, 공유 시트 링크 하나로 역질문·피드백 표를 양방향 동기화할 수 있습니다.
