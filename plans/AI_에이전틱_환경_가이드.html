AI AGENT VS AGENTIC SYSTEM

“우리는 AI를 ‘도구’로 쓰고 있나요,
‘시스템’으로 사용하고 있나요?”

파편화된 개인별 AI 활용(AI Agent)을 넘어,
기획·디자인·개발이 하나의 정본으로 맞물리는 AI 에이전틱 시스템(Agentic System)

01. 전체 시스템 조감도 보기 ↓
SECTION 01-A · CONCEPTUAL ARCHITECTURE (3-LANE SWIMLANE)

전체 시스템 조감도 — Lane 1 ~ Lane 3 유기적 순환 구조

PO/PM의 요구사항 정의(하향)와 구현 중 발견된 미정의 정책 질의(상향)가 Git 정본 허브를 통해 순환합니다.

SECTION 01-B · ROLE PARADIGM SHIFT

파이프라인 전(Before) vs 후(After) — 직군별 사람의 핵심 역할

수동 문서 중계와 기계적 대조는 시스템에 맡기고, 사람은 정의(Definition)와 승인(Approval)에 집중합니다.

PO / PM 그룹 수동 중계 0%

변경할 정책을 정의하면 AI가 연관 화면코드를 모두 찾아 정본과 LATEST_TASK.md를 동시에 갱신합니다.

UIX 디자이너 시안 임의 변형 차단

Ready for Dev 상태의 Figma 프레임만 MCP로 직결되어 개발 단계에서 디자인이 틀어지지 않습니다.

FE / BE 개발자 API Mock 병렬 개발

백엔드 완성 전에도 00_domain_contracts.md의 표준 API Mock 스키마를 바인딩해 즉시 개발합니다.

SECTION 02 · 4-STAGE WORKFLOW & FEEDBACK LOOP

4단계 에이전틱 파이프라인 & 역방향 환류 루프

정방향(01→04) 자동 실행과 함께, 검수 단계(04)에서 발견된 위반·질의가 앞 단계로 즉시 환류됩니다.

01 정본화 구두 합의 배제

정본에 정의되지 않은 요구사항은 구현 대상에서 제외하여 단일 기준을 유지합니다.

02 UI 직결 프로토타입 유지보수 생략

수십 개 정적 HTML을 수작업 관리하는 대신 표준 UI 템플릿과 Figma MCP를 직결합니다.

03 타겟 구현 컨텍스트 혼선 차단

작업 화면에 해당하는 6% 요약 명세만 적재해 타 도메인 규칙과의 혼동을 막습니다.

04 양방향 환류 자동 대조 & 역동기화

코드 위반은 커밋 전 차단하고, 미정의 정책은 질의 큐를 통해 정본으로 환류시킵니다.

SECTION 03 · 2-REPO ARCHITECTURE

저장소 물리적 분리 — 정본 저장소(spec-repo) vs 개발 저장소(app-repo)

기획·디자인 정본 자산과 애플리케이션 소스코드를 분리하고 스크립트로 동기화합니다.

원칙 1 컨텍스트 오염 원천 차단

기획 문서·초안과 실제 프로덕션 코드가 섞여 AI가 구버전 예시를 참조하는 오류를 방지합니다.

원칙 2 직군별 변경 권한 분리

정본 저장소(spec-repo)는 PO/PM이, 개발 저장소(app-repo)는 개발팀이 승인 권한을 갖습니다.

원칙 3 로컬 스킬 + 중앙 CI 결합

유료 외부 서버 없이도 각자 로컬 스킬로 정합성을 맞추고, 중앙 CI는 check.sh로 코드만 검증합니다.

SECTION 04 · TOKEN & CONTEXT EFFICIENCY

토큰 94% 절감 — 화면별 요약 명세(Digest) 타겟 로드

전체 정본을 통째로 읽히는 대신, 작업 대상 화면 1개에 필요한 6% 핵심 명세만 선별 적재합니다.

전략 1 색인(canon_index) & Digest

화면코드별 줄 번호 색인과 1장 요약 명세를 통해 필요한 구간만 정확히 발췌하여 읽습니다.

전략 2 결정론적 검사의 스크립트 위임

코드 스타일, 임시 DB 테스트, 도메인 계산기 대조는 AI 토큰 대신 check.sh가 수행합니다.

전략 3 화면 단위 컨텍스트 리셋

화면 1개 구현·검수가 끝나면 세션을 초기화(/clear)하여 누적 토큰 비용을 차단합니다.

SECTION 05 · 2-TRACK UI STRATEGY

프로토타입 관리 부담을 없애는 2-Track 화면 설계

백오피스(Track A)와 유저 프론트(Track B)의 시각 정본을 분리해 정적 HTML 유지보수 비용을 제거합니다.

Track A 효과 어드민 화면 통일성 100% 보장

여러 개발자가 병렬로 작업해도 동일한 4종 표준 UI 템플릿을 사용하므로 레이아웃 파편화가 발생하지 않습니다.

Track B 효과 디자이너 의도 무손실 반영

개발자 AI가 DOM이나 스타일을 임의로 바꾸지 못하고 Figma 시안 위에 데이터 바인딩과 API 로직만 연결합니다.

SECTION 06 · TASK SPEC, POLICY INQUIRY & FAST-TRACK

변경 작업 명세 배포 · 미정의 정책 질의 & 3단계 패스트트랙

외부 툴 없이 Git 내 LATEST_TASK.md와 QUESTIONS.md 양방향 루프로 소통이 완결됩니다.

💡 사내 업무플랫폼(자체 구축 게시판)이나 외부 협업 툴과 연동하려면?

Git 기본 코어 위에 사내 업무플랫폼 경량 API 3종(project-meta.json 다중 프로젝트·부서별 담당자 자동 매핑) 또는 Google Workspace를 연결하는 확장 제안입니다.

SECTION 07 · 5 CORE AI SKILLS

직군별 5대 핵심 AI 스킬(/) 체계

AI 실행 명세서(AI_에이전틱_환경_구축.md)에 정의된 5개 표준 명령어로 전 과정을 구동합니다.

01 · 초기/역공학

/doc-init

신규 기획 초안이나 레거시 코드를 분석해 표준 3단 정본(v1.0.0), 색인, 요약 명세(Digest)를 최초 생성합니다.

02 · 공통 계약

/doc-rule

도메인 공통 계약(API Mock JSON 포함 00_domain_contracts.md)과 2-Track 표준 UI 계약을 추출·갱신합니다.

03 · PO / PM 상시

/doc-update

요구사항 정의 시 변경 등급(L1~3)과 영향 화면코드를 스캔해 정본·계산기·LATEST_TASK.md를 일괄 개정합니다.

04 · FE / BE 상시

/dev-screen

LATEST_TASK.md와 6% 타겟 명세 및 Track A/B UI 소스를 결합해 구현하고 미정의 정책은 질의로 분리합니다.

05 · 양방향 검수

/spec-check

정본 명세·계산기 정답셋·Figma 시안과 실제 코드를 대조해 일치(✅)·위반(❌)·임의구현(⚠️)·질의(❓)를 판정합니다.

🚀 프로젝트 유형별 도입 로드맵 & AI 주입용 실행 명세서(.md)

신규 구축 / 전면 리뉴얼 / 운영 고도화별 도입 순서를 확인하거나, AI 에이전트에게 바로 읽힐 실행 명세서 정본을 다운로드하세요.

📖 핵심 용어 사전 (Glossary)

용어 (약어) 한글 비즈니스 명칭 실무 역할 및 쉬운 풀이
SSOT
Single Source of Truth		 단일 정본 (유일 기준 원본) 기획서·정책서·화면 명세가 여러 곳에 흩어지지 않고 오직 spec-repo/docs/의 문서만 절대 기준으로 삼는 원칙.
LATEST_TASK.md 변경 작업 명세서 PO/PM이 요구사항을 정의할 때 Git에 자동 생성·배포되는 파일. UIX·개발의 로컬 AI가 sync-spec.sh 직후 스스로 읽고 이번 작업 범위를 파악함.
QUESTIONS.md 미정의 정책 질의서 구현·검수 중 정본에 정의되지 않은 예외 케이스 발견 시 AI가 임의 추론 대신 질의(❓)를 등록해 PO/PM 의사결정으로 환류시키는 큐.
Digest
Screen Digest		 화면별 요약 명세 (1장 요약본) 전체 정본 중 특정 화면 코드 1개 구현에 필요한 필드·상태·모달·수식만 1~2장으로 자동 추출한 AI 타겟 로드용 명세(토큰 94% 절감).
MCP
Model Context Protocol		 외부 도구 직결 프로토콜 AI가 로컬 파일뿐 아니라 Figma 디자인 시안, 사내 업무플랫폼 API 등 외부 데이터를 실시간으로 읽어오는 표준 연결 규격.
Archetype
UI Archetype		 표준 UI 템플릿 (4종) 별도 디자인 시안 없이도 백오피스 화면의 통일성을 유지하는 4대 레이아웃 템플릿 (List-Modal, Detail-Form, Stats-Dashboard, Tabs-Complex).
Fast-Track (L1~L3) 변경 등급별 경량 경로 신규/대규모(L1) · 로직만 변경(L2, UIX 생략) · 단순 문구/긴급 패치(L3, 선조치 후 역동기화)로 나누어 처리 속도를 높이는 규칙.
Greenfield / Brownfield 신규 구축 / 레거시 유지보수 백지상태에서 새로 구축하는 프로젝트(Greenfield)와 기존 레거시 코드 위에서 기능을 고도화하는 프로젝트(Brownfield).

🔌 자사 피드백 전달 방식 — Git 기본 코어 & 사내 업무플랫폼 확장 연동 제안

Option A (권장 확장) 사내 업무플랫폼 경량 API

자체 구축된 사내 업무플랫폼에 경량 API 3종만 개방하면 됩니다. 다중 프로젝트 ID와 부서별 담당자 지정은 초기 1회 동기화한 project-meta.json을 참조해 AI가 도메인에 맞춰 자동 배정합니다.

Option B (대안 확장) Google Workspace 연동

사내 플랫폼 API 개방 전 과도기나 외부 협업 시에는 기본 내장된 Google Sheets / Chat 플러그인을 통해 작업 상태판과 정책 질의 스레드를 자동 동기화할 수 있습니다.
