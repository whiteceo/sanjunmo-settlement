01 Master Conceptual Architecture: 전체 작동 조감도

외부 툴 없이도 Git 내장 지시서(`LATEST_TASK.md`)만으로 100% 완결되는 기본(Core) 구조와, 사내 업무플랫폼 API·구글 워크스페이스를 붙이는 확장 제안(Option)을 아우르는 최상위 개념도입니다.

02 토폴로지 비교: 왜 ‘단일 정본(SSOT) + 로컬 스킬’ 구조인가?

왼쪽(각자도생 AI 코딩으로 인한 충돌과 PO/PM 검수 병목)과 오른쪽(단일 정본 허브 + 로컬 스킬 통제)의 구조 비교입니다.

03 컨텍스트 깔때기(Funnel) 도식: 수천 줄 기획서를 어떻게 6%로 줄이는가?

대형 기획서를 통째로 넣지 않고, LATEST_TASK.md가 태깅한 화면 코드를 열쇠로 삼아 해당 화면에 필요한 6% 명세만 핀셋 추출합니다.

04 전체 작동 회로도: PO/PM 안건 지시 ➔ Git 지시서 전파 ➔ 분기(역질문) ➔ 검수

외부 툴 없이도 LATEST_TASK.md(Git 내장 변경 지시서)와 QUESTIONS.md를 매개로 순환하는 엔드투엔드 작동 회로도입니다.

05 화면·프론트엔드 2-Track 도식: 프로토타입 없이 UI 통일성 & UIX(Figma) 직결하기

무거운 HTML 프로토타입 파일을 수작업으로 관리하지 않고, 화면 성격에 따라 Track A(백오피스 표준 골격)와 Track B(UIX 디자이너 Figma MCP 직결)로 이원화합니다.

06 사람(Human) 시점의 파이프라인 전/후 역할 & 지시·피드백 전달 구조

다수의 PO/PM · UIX 디자이너 · FE/BE 개발자가 파이프라인 전/후에 하는 일과, Git 내장 지시서(기본 Core) vs 사내 업무플랫폼 API(확장 제안) 구조입니다.

지시·피드백 전달 방식 구분: 기본(Git 내장 지시서 MD) vs 확장 제안(사내 업무플랫폼 API / GWS)
구분 [기본 (Core · 필수)] Git 내장 지시서 (`LATEST_TASK.md`) [확장 제안 A (Optional)] 사내 업무플랫폼 API 직결 [확장 대안 B (Optional)] Google Workspace 연동
도입 조건 및 성격 추가 개발 0건 · 즉시 가동 (Git 저장소만으로 100% 완결) 사내 업무플랫폼 담당자와 협의 후 경량 REST API 3종(등록·조회·상태변경) 추가 시 적용 사내 플랫폼 협의 전 과도기 또는 외부 협업 시 AI 내장 GWS 도구 활용
지시 전달 방식 (복붙 0%) PO/PM이 `/doc-update` 실행 시 `docs/changes/LATEST_TASK.md`에 변경 안건·영향 화면코드·파트별 지시사항이 생성되어 Git 푸시됨. 개발자는 `sync-spec.sh` 후 AI가 이 파일을 바로 읽음 초기 1회 동기화한 `project-meta.json`(프로젝트 ID + 부서/도메인별 담당자 명단)을 바탕으로 AI가 사내 업무플랫폼에 안건과 담당자를 자동 지정해 게시 AI가 공유 Google Sheets(안건 상태판) 및 Google Chat 스페이스에 변경 사항을 자동 기록
역질문(`❓`) 수렴 방식 개발 중 미정의 케이스 발견 시 `docs/changes/QUESTIONS.md`(또는 PR 코멘트)에 기록 ➔ PO/PM의 AI가 읽고 정본 보완 UIX·개발자가 사내 게시판 스레드에 댓글 등록 ➔ PO/PM의 AI가 `GET` API로 댓글을 직접 읽어와 브리핑 Google Sheets 코멘트 또는 Chat 스레드를 AI가 직접 읽어와 브리핑

정본 없는 레거시 서비스를 온보딩하는 /doc-init 원리와 5대 스킬 체계, 프로젝트 유형별 로드맵 및 용어 사전입니다.

📖 핵심 용어 사전 (Glossary)

SSOT (단일 정본 · Single Source of Truth)

기획서·정책서가 여러 곳에 흩어지지 않고 오직 정본 저장소(`spec-repo/docs/`)의 문서 하나만 유일한 정답 기준으로 삼는 원칙입니다.

LATEST_TASK.md (Git 내장 변경 지시서)

외부 툴 없이도 PO/PM의 `/doc-update` 실행 시 Git에 자동 생성되는 지시서로, 개발자 AI가 `git pull` 직후 읽고 이번 작업 범위와 영향 화면코드를 즉시 파악합니다.

PO / PM (프로덕트 오너 / 매니저)

비즈니스 정책과 화면 기획을 수립하고 단일 정본(SSOT)의 최종 승인 권한을 갖는 기획 책임자 그룹(다수 도메인 PM 포함)입니다.

MCP (모델 컨텍스트 프로토콜 · 외부 도구 직결 통로)

로컬 AI가 UIX 디자이너의 Figma 시안 데이터를 사람 손 빌리지 않고 실시간으로 직접 읽어오는 표준 연결 규격입니다.

Digest (화면별 1장 요약본)

수천 줄짜리 전체 기획서 중 특정 화면 코드 1개에 필요한 필드·상태값·모달·수식만 1~2장으로 자동 발췌한 AI 전용 요약 카드입니다.

Archetype (표준 화면 골격 4종)

HTML 프로토타입 없이도 백오피스 화면이 일관되게 나오도록 규정한 4가지 표준 레이아웃 틀(목록+모달, 상세폼, 통계, 복합탭)입니다.

Auto Layout & Design Token (자동 배치 & 디자인 변수)

Figma에서 여백·반응형 정렬과 색상·폰트 변수를 규격화해 두어, AI가 눈대중 코딩 없이 디자인을 100% 똑같이 구현하게 하는 설정입니다.

Fast-Track L1~L3 (변경 등급별 경량 경로)

신규/UI변경(L1 풀코스), 화면 변경 없는 수식/로직 수정(L2 UIX 생략), 단순 문구·긴급 장애(L3 선조치 후동기화)로 나눈 처리 경로입니다.
