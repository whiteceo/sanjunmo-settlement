AI Agentic SDLC Playbook v1.0

AI 에이전틱 개발 · 정합성 검증 환경 가이드

다수의 개발자가 각자 로컬에서 Claude Code로 개발하더라도, 단일 기획 정본(SSOT)에서 벗어나지 않고 도메인 간 비즈니스 로직 충돌을 자동으로 감시·차단하는 표준 작업 체계입니다.

1. 로컬 AI의 ‘각자도생’ 차단 누가 로컬에서 AI를 돌리든 동일한 정본 색인·요약본·공통 계약만 참조해 임의 추론을 원천 방지
2. 도메인 간 로직 충돌 예방 회원·정산 ↔ 주문·환불 ↔ 게시판·권한 경계의 공통 코드·상태값 규칙을 도메인 계약서로 강제
3. PO의 수동 검수 병목 제거 각자 로컬에서 전용 스킬(/doc-update · /dev-screen · /spec-check)을 거쳐 정합성 자동 검증

1 전체 저장소 구조 (정본과 코드의 결합 방식)

정본 저장소와 개발 저장소를 분리하되, 로컬 동기화 브릿지(Spec Bridge)로 모든 AI가 같은 정본을 참조합니다.

2 각자 로컬에서 실행하는 ‘5대 핵심 스킬’

별도 외부 서버 과금 없이, PO와 개발자가 각자 로컬 Claude Code에서 직관적인 명령어로 실행합니다.

/doc-init
① 초기 정본 만들기
정본이 없는 레거시 코드나 초안 문서를 스캔해 화면 코드를 부여하고, 표준 3단 템플릿([A]·[B]·[C]) 정본 v1.0.0과 색인·요약본을 최초 생성합니다.
🕒 사용 시점: 신규/레거시 프로젝트 최초 온보딩 시 (1회)
/doc-rule
② 공통 규칙 뽑기
수천 줄의 기획서에서 여러 개발자 도메인이 공유하는 코드 채번(RH-*, CT-*, PROD-BK-*), 공통 상태값, 소속 3분류만 뽑아 1장짜리 계약서로 만듭니다.
🕒 사용 시점: 초기 세팅 & 공통 스키마·코드 변경 시
/doc-update
③ PO 정책 변경
정책 수정 시 영향받는 모든 문서 절과 화면 코드를 먼저 스캔해 보고하고, 승인 시 문서·프로토타입·계산기 일괄 수정 + 문서 개정 이력 기록 + 개발팀 티켓을 생성합니다.
👤 사용 주체: PO (white) — 정책·화면 규칙 개정 시 상시
/dev-screen
④ 개발자 화면 구현
/dev-screen ADMN-SETT-005처럼 화면 코드만 치면, 기획서 전체 대신 해당 화면의 정본 구간 + 요약본 + 공통 규칙만 핀셋 로드해 코딩하고 check.sh까지 돌립니다.
👩‍💻 사용 주체: 개발자 4명 — 담당 화면 코딩 시 상시
/spec-check
⑤ 정본 대조 검수
정본 명세와 현재 코드를 1:1 대조하여 ✅ 일치 / ❌ 정본 위반·누락 / ⚠️ 정본에 없는 임의 구현 3가지로만 판정 리포트를 출력합니다.
🔍 사용 주체: 개발자(커밋 직전) & PO(수시 총괄 감사)

3 일일 작업 순환 흐름도 (PO 개정 → 개발자 구현 → 검수·배포)

PO가 정책을 바꿀 때와 개발자가 커밋할 때 어떻게 정합성이 체크되는지 보여주는 3단계 흐름입니다.

STEP A. PO 정책 개정 PO 로컬 AI
A-1 정책 변경 지시
PO가 로컬 AI에게 /doc-update로 변경할 정책(예: 환불 규정 수정)을 지시합니다.
A-2 영향 화면 전수 스캔 & 일괄 개정
AI가 영향받는 문서 절과 화면 코드(ADMN-RFD-002, USER-MY-011 등)를 찾아 보고하고, 승인 시 정본·프로토타입·계산기를 동시 수정합니다.
A-3 문서 개정이력 기록 & 개발팀 전달
상단 문서 개정 이력 표에 새 버전(v3.2.xx)과 영향 화면 코드를 남기면, 개발 레포의 담당자(박성민·노승원·이응민)별 수정 요청이 생성됩니다.
STEP B. 개발자 화면 구현 개발자 로컬 AI
B-1 화면 코드로 작업 시작
개발자가 자기 PC에서 /dev-screen 화면코드를 실행하면 최신 정본 동기화 후 해당 화면 명세만 가볍게 읽어옵니다.
B-2 미확정 정책 차단 & 계층 구현
정본에 없는 규칙은 임의로 짜지 않고 즉시 질문으로 빼며, 확정된 규칙만 Controller → Service → Repository 구조로 구현합니다.
B-3 커밋 직전 셀프 대조 & 체크
커밋 전 /spec-check로 정본 누락이 없는지 확인하고, bash scripts/check.sh(Pint + 임시 MySQL 테스트)를 통과한 뒤 커밋합니다.
STEP C. 병합 · 총괄 감사 GitHub + PO
C-1 결정론적 자동 테스트 (GitHub)
dev 병합 시 전체 도메인 테스트와 정산 기준 계산기(61건 시나리오) 일치 여부를 기계적으로 검증합니다.
C-2 개발 진행률 자동 갱신
커밋 메시지에 적힌 화면 코드(ADMN-*, USER-*)와 DECISIONS 번호를 읽어 진행률 대시보드를 자동 갱신합니다.
C-3 PO 수시 총괄 감사
PO가 필요할 때 로컬에서 /spec-check를 돌려 양쪽 폴더(정본 ↔ 개발 코드)의 위반·임의 구현 여부를 한눈에 리포트로 확인합니다.

4 환경 셋팅(기계)과 운영 규약(사람)의 역할 분담

기계가 자동으로 해주는 영역과, 사람이 반드시 지켜줘야 하는 5가지 최소 약속입니다.

⚙️ Part A. 시스템 환경 셋팅 (기계가 강제하는 영역)

1. 정본 브릿지 (scripts/sync-spec.sh) 정본 레포의 위치 색인(canon_index.md), 화면 요약본(digest/), 공통 계약(00_domain_contracts.md), 정산 61건 정답셋을 개발 레포의 docs/로 자동 연결합니다.
2. 로컬 AI 제어 지침 (sanjunmo/CLAUDE.md) 모든 개발자의 Claude Code가 켜질 때 자동으로 읽는 최상위 규칙으로, 대형 문서를 통째로 읽지 않고 색인·요약본 기반으로만 코딩하도록 강제합니다.
3. 커밋 프리체크 가드 (scripts/check.sh) 내가 수정한 파일의 Pint 문법 검사와 격리된 임시 MySQL 8.4 컨테이너 4병렬 테스트를 통과해야만 .claude/check-pass 표식이 생성됩니다.
4. 정산 엔진 61건 Parity 테스트 정본에서 이미 검증된 PHP 8.4 기준 계산기의 61건 입출력 JSON을 개발 레포 테스트에 그대로 연결해 1원 단위 오차도 허용하지 않습니다.

🤝 Part B. 사람들이 지켜야 할 5대 규약 (팀 프로토콜)

규약 1. 모든 작업과 커밋에는 ‘화면 코드’를 반드시 적는다 브랜치·AI 지시·커밋 메시지에 (ADMN-SETT-005 · DECISIONS 208)처럼 화면 코드를 적어야 스킬이 정본을 찾고 진행률이 집계됩니다.
규약 2. [PO] 구두·메신저 지시 대신 /doc-update로 정본을 먼저 고친다 구두로만 바꾸라고 하면 개발자 코드가 /spec-check에서 ‘정본 위반’으로 잡힙니다. 항상 정본과 문서 개정 이력을 먼저 갱신합니다.
규약 3. [개발자] 코딩 시작은 /dev-screen, 커밋 전엔 /spec-check 작업 시작 전 정본을 최신화하고, 커밋 직전 셀프 대조(/spec-check)와 check.sh를 통과한 코드만 올립니다.
규약 4. [개발자] 정본에 없는 정책은 임의로 짜지 않고 질문한다 애매한 예외 케이스를 AI가 추론해 짜지 못하게 막고, PO에게 알려 정본(DECISIONS)에 먼저 확정한 뒤 구현합니다.
규약 5. [개발자] 타 담당자의 도메인 테이블을 직접 수정하지 않는다 남의 도메인 모델/테이블을 직접 건드리지 않고 00_domain_contracts.md에 정의된 Service/Event만 호출합니다.

5 전사 확장: 신규 프로젝트 및 유지보수(레거시) 서비스 적용 비교

이 체계는 산준모뿐 아니라 신규 프로젝트와 정본이 없는 유지보수 서비스 모두에 동일하게 적용됩니다.

프로젝트 유형별 AI 에이전틱 환경 도입 방식 비교
구분 산준모 프로젝트 (현재 진행 중) 신규 구축 프로젝트 (Greenfield) 유지보수 레거시 서비스 (Brownfield)
초기 정본 상태 정본·프로토타입·계산기·색인·Digest 이미 완비됨 코드 0 상태에서 정본부터 작성 시작 정본이 없거나 옛날 문서만 있고 레거시 코드만 돌아가는 상태
첫 단계 (Day 1) /doc-rule로 00_domain_contracts.md 생성 후 바로 /spec-check로 현행 코드 대조 보일러플레이트(CLAUDE.md + 5대 스킬 + check.sh) 복제 후 /doc-init으로 시작 /doc-init (초기 정본 만들기 스킬)을 돌려 레거시 코드에서 역으로 정본 v1.0.0 + 색인 + Digest 자동 추출 (의심 로직은 PO 질문지로 분리)
기존 기술부채 처리 check.sh가 기존 위반 파일은 경고만, 신규/수정 파일만 엄격 검사 첫 커밋부터 기술부채 0건 유지 레거시 전체 리팩토링 없이, 이번에 유지보수로 건드리는 화면부터 점진적 정본화 (Touch-and-Lock)
일상 운영 루프 PO 정책 개정(/doc-update + 문서 개정이력) ➔ 개발자 화면 구현(/dev-screen) ➔ 커밋 전 대조 검수(/spec-check + check.sh) 100% 동일
